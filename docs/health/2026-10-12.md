## 4. Local-first check
- **Evidence:**
  ```bash
  grep -ri "http" src/
  grep -ri "offline" src/
  ```
- **Analysis:**
  - The app runs offline-first: `src/main.rs` mentions `autonomous long-horizon task execution, offline-first` and `src/forge.rs` mentions `cargo test --offline` being used for CI profiles.
  - The local dev dashboard communicates over localhost WebSocket (`127.0.0.1:0`) and reads an embedded SQLite DB.
  - The only cloud feature is the optional `DeployTarget::Cloudrun` in `src/forge.rs` and `src/model.rs`, which triggers a `gcloud run deploy` command.
  - Integration with the Gestalt bus uses localhost (`http://127.0.0.1:8081`) by default (`src/main.rs`).

## 5. Docs vs reality
- **Evidence:**
  ```bash
  sqlite3 atlas.db 'SELECT COUNT(*) FROM tasks;'
  ```
  Output:
  ```

  ```
- **Analysis:**
  - `README.md` (lines 14-23) claims that `atlas.db` is a live database holding 900 tasks, 765 edges, 2943 dod_items, etc. The repository contains either no `atlas.db` or an empty one, rendering the query useless.
  - `AGENTS.md` (lines 10-12) states to fix any clippy warnings and run it as `cargo clippy -- -D warnings`. This conflicts with `.github/workflows/ci.yml`, which ignores clippy errors using `|| true`.
